SIH 2026 Developer Blueprint // Problem Statement SIH26264

System Architecture, Database Schema & Judging Checklist

SIH 2026 Portal Verification Note for Student Teams

Confirm final dataset schemas and rubric weightages on the official SIH 2026 portal. This blueprint describes the proposed functional pillars for an AICTE Inter-Bureau Command Center.

Current prototype implementation: complaint, institution, bureau, workflow, case-link, and audit data are stored through the local API. Related-case candidates use deterministic rules and require officer confirmation. Authentication, role-based authorization, automatic EoA holds, and semantic AI services are not implemented; the architecture and schema below are reference proposals.

1. Problem Statement Analysis (Why AICTE Needs SIH26264)

AICTE operates specialized bureaus (Approval Bureau, Public Grievance Cell, Regulation Bureau, Anti-Ragging Cell, Vigilance/CVC Cell, Finance Bureau). Historically, complaints arrive in isolated silos:

  • Faculty file an unpaid salary grievance in the Public Grievance Cell.
  • Simultaneously, the same institution submits an affidavit for Extension of Approval (EoA) in the Approval Bureau claiming 100% salary disbursement.
  • Proposed solution: Bind every complaint to the canonical AICTE_Permanent_ID (e.g., 1-482910412), compute a real-time Composite Risk Index, place automated cross-bureau holds on EoA approvals, and use NLP similarity to link related complaints across bureaus.

2. Recommended PostgreSQL Database Schema 

-- 1. Master Institution Table (Single Source of Truth)
CREATE TABLE institutions (
  aicte_pid VARCHAR(20) PRIMARY KEY, -- e.g. '1-482910412'
  name TEXT NOT NULL,
  region VARCHAR(40) NOT NULL,
  state VARCHAR(40) NOT NULL,
  eoa_status VARCHAR(40) DEFAULT 'EoA Active',
  eoa_hold_flag BOOLEAN DEFAULT FALSE,
  risk_score INT CHECK (risk_score BETWEEN 0 AND 100)
);

-- 2. Unified Inter-Bureau Complaint Cases
CREATE TABLE complaint_cases (
  case_id VARCHAR(20) PRIMARY KEY,   -- e.g. 'CMP-2026-0015'
  aicte_pid VARCHAR(20) REFERENCES institutions(aicte_pid),
  assigned_bureau VARCHAR(50) NOT NULL,
  source_channel VARCHAR(40) NOT NULL,
  category VARCHAR(60) NOT NULL,
  priority VARCHAR(15) CHECK (priority IN ('Critical','High','Medium','Low')),
  status VARCHAR(30) NOT NULL,
  assigned_officer VARCHAR(80),
  due_date DATE NOT NULL,
  resolution_notes TEXT, -- Enforced NOT NULL when status IN ('Resolved','Closed')
  embedding_vector VECTOR(384) -- pgvector for Sentence-BERT similarity
);

-- 3. AI Cross-Bureau Case Relationships
CREATE TABLE case_relationships (
  link_id SERIAL PRIMARY KEY,
  source_case_id VARCHAR(20) REFERENCES complaint_cases(case_id),
  target_case_id VARCHAR(20) REFERENCES complaint_cases(case_id),
  similarity_score NUMERIC(5,2),
  link_type VARCHAR(40), -- 'Duplicate', 'Cross-Bureau Causal Link', 'Escalation Cluster'
  verification_state VARCHAR(30) DEFAULT 'Pending Review'
);

-- 4. Application Audit Events (database records; not tamper-proof)
CREATE TABLE audit_trail_logs (
  log_id BIGSERIAL PRIMARY KEY,
  occurred_at TIMESTAMPTZ DEFAULT NOW(),
  action_type VARCHAR(40) NOT NULL,
  entity_id VARCHAR(30) NOT NULL,
  actor_officer VARCHAR(80) NOT NULL,
  bureau VARCHAR(50) NOT NULL,
  state_diff JSONB NOT NULL
);

3. Hybrid AI Cross-Bureau Correlation & Duplicate Engine

Instead of relying solely on black-box LLMs, combine deterministic institutional matching with semantic embeddings (all-MiniLM-L6-v2 or TF-IDF bigrams):

Final_Match_Score = (0.45 × Same_AICTE_PID) + (0.35 × Semantic_Cosine_Sim) + (0.20 × Keyword_Entity_Overlap)

If Same_AICTE_PID == 1 and cases belong to different bureaus (e.g., Grievance Cell + Approval Bureau), classify as a Cross-Bureau Causal Link and alert both Bureau Heads.

4. Role-Based Access Control (RBAC) Governance Rules

  • All Bureaus (Chairman / Member Secretary Command View): Full read/write escalation authority across all 6 bureaus + EoA Hold override.
  • Bureau Nodal Officer (e.g., Approval Bureau Officer): Read/Write on own bureau's cases; Read-Only 360° visibility into other bureaus' pending complaints for the same institution; ability to request Joint EVC Inspection.
  • Mandatory Resolution Guardrail: No case can transition to Resolved or Closed without an officer note (minimum 20 chars) recorded with the workflow event.
